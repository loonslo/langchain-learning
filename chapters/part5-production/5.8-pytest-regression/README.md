# 5.8 pytest 回归：让已知质量问题自动报警

[全书目录](../../README.md) · [上一章 5.7](../5.7-security-guardrails/README.md) · [下一章 6.1](../../part6-model-tradeoffs/6.1-choose-prompt-rag-finetune/README.md)

- **目标**：把评测变成 pytest 回归测试：改完 RAG 一条命令跑回归，答错的立刻红灯。
- **前置**：2.6、3.2；`DEEPSEEK_API_KEY`；本地 embedding 模型。
- **环境**：调用真实模型；环境没配好时用例会跳过并说明原因。
- **命令**：`python tools/run_chapter.py 5.8`（可追加 pytest 参数，如 `--collect-only -q`）

## 问题

刚修改了 RAG 的提示词，人工试问一次觉得不错，但原来能答对的事实可能已被破坏。对测试工程师来说，下一步很熟悉：把固定问题变成可重复运行的用例，让退化有明确的失败记录。

## 概念

- **fixture**：整个会话只建一次检索链（`scope="session"`），embedding 模型只加载一次；`ask` 按问题缓存本轮答案，一个问题只调用一次模型，断言可以有很多条。
- **参数化**：`@pytest.mark.parametrize` 把每条问题变成独立用例，失败报告可以回到具体问题。
- **不用精确断言**：模型输出有随机性，用“包含关键词 / 是否拒答”的宽松断言，并把 `temperature` 设为 0。关键词判定要归一化（全角半角、大小写、空格），并支持“同义词任选其一”，否则测的是措辞习惯。
- **skip 与 fail 分开**：环境缺失造成 skip，质量不满足造成 fail。CI 里设 `RAG_TEST_STRICT=1`，让“环境没配好”也变成红灯，避免回归被静默跳过。
- **路径相对本文件**：CI 里 pytest 的工作目录不一定是仓库根目录。
- **失败留痕**：跑完把结果写进 `reports/regression_results.json`，便于逐题复查。
- **延迟也要回归**：`RAG_TEST_LATENCY_MS` 设定单次问答的延迟预算。

## 流程

1. `load_cases` 合并内置用例（`BASE_CASES`：三个事实问题、两个拒答问题）和可选的外置用例库 `regression_cases.json`。
2. `rag_chain` 检查环境（密钥、测试文档、embedding 模型），只建立一次检索链。
3. `ask` 按问题缓存答案。
4. 正例先排除拒答，再检查每组关键词；负例检查拒答。
5. 延迟检查，并把结果落盘。

## 跟着一个回归例子走

假设刚把提示词改成“回答尽量简短”。问题“RAG 是什么”应至少表达“检索”和“生成”两个事实。如果只答“是一种回答方式”，句子通顺，必要事实却没有覆盖，测试应当失败。

再看一个更隐蔽的情况：回复“文档中没有提到如何检索”。它包含“检索”这个关键词，却是在拒答。正例必须先排除拒答再判断关键词，否则测试会制造一盏假绿灯。

| 输入或状态 | 预期观察 | 为什么 |
|---|---|---|
| 文档支持的事实问题 | 覆盖每组必要关键词，且不是拒答 | 允许表达变化，事实要求不能丢 |
| 文档没有覆盖的问题 | 明确拒答 | 不能用模型常识冒充资料证据 |
| 缺密钥或嵌入模型 | 默认跳过并说明缺项 | 尚未判断质量 |
| 严格模式中缺环境 | 失败 | 验收不能静默跳过 |
| 回答超过延迟预算 | 延迟检查失败 | 功能与响应时间分别验收 |

运行后先读通过、失败、跳过三种数量，再读逐题记录。全被跳过，意味着没有取得真实的质量证据。即使全部通过，关键词规则也没有检查完整语义和引用支持关系，这些仍需要后续评测。

## 代码导读

[rag_regression.py](rag_regression.py)：先读 `BASE_CASES`，再读 `_norm`、`_refused`、`_missing_keyword`，最后读 `rag_chain`、`ask` 和三个 `test_*` 函数。对每个断言写出它能识别什么、遗漏什么。[test_doc.txt](test_doc.txt) 是本章自带的合成资料（不是真实公司政策），关键词都能在里面核对。

## 练习

1. 先手工判断“包含‘检索’一词的拒答句”该不该算正确，再对照实现。
2. 用 `test_doc.txt` 核对每组关键词确实来自文档。
3. 运行后分别统计 pass、fail、skip，并从 `regression_results.json` 追到一条原始问题。
4. 把 3.7、3.10 里曾经答错的问题写进 `regression_cases.json`（相同的 `id`、`question`、`keywords`、`should_refuse` 结构），让它们永远被回归覆盖。

## 运行与边界

- 关键词与拒答规则不覆盖完整事实和引用质量。capstone 的真实模型回归里有一个已知问题：拒答时仍附带无关引用，详见 TASKS.md。
- 会调用真实模型并产生费用。
