# 5.3 成本、缓存与路由：收益需要实际测量

[全书目录](../../README.md) · [上一章 5.2](../5.2-reliability-retry/README.md) · [下一章 5.4](../5.4-sqlite-persistence/README.md)

- **目标**：用缓存和模型路由降低调用成本，并理解“路由阈值要由评估驱动”。
- **前置**：5.2；`DEEPSEEK_API_KEY`。
- **环境**：调用真实模型；工程版路由需要本地 embedding 模型。
- **命令**：`python tools/run_chapter.py 5.3`

## 问题

LLM 按 token 收费，规模上来后成本可观。两招最常用：重复的问题直接返回上次的结果；简单问题用便宜的小模型，复杂问题才用贵的大模型。

## 概念

- **缓存**：以问题的哈希为键、答案为值。省 token 也降延迟；生产里可换 Redis（9.7），并要考虑过期、权限和知识版本。
- **规则版路由**：`is_simple` 按“短、像闲聊”判断，只是冷启动，容易误判。
- **工程版路由闭环**：A. 离线定标（一次性）：便宜模型作答，强模型当裁判判断“答对了吗”，答对的记为“简单”，难度由实测定义；B. 在线（每次请求）：用本地 embedding 的两个质心做分类，推理本地完成，不花 token；C. 监控：抽样 1–5% 请求让裁判复核便宜模型的答案，发现漂移就重新标注。
- **算账决定取舍**：省钱幅度 ≈ 简单问题占比 ×（1 − 便宜模型与强模型的价差比）。两个数都要从日志和离线评估里量出来，不靠感觉。

## 流程

1. 同一个问题问两次，第二次命中缓存，不调用模型。
2. 规则版路由：“你好”走便宜模型，“详细对比 RAG 和微调……”走强模型。
3. 工程版：用 `SEED_LABELED`（演示用的种子标注）建立 `EmbeddingRouter`，对两个问题分类；`ask_production` 走完整链路，并以 5% 的概率抽检。

## 代码导读

[cost_cache_routing.py](cost_cache_routing.py)：先看 `ask_with_cache`，再看 `is_simple`，最后按 A、B、C 三段看工程版：`offline_label`、`EmbeddingRouter`、`ask_production`。演示里的“便宜模型”和“强模型”用的是同一个模型，请换成你自己的两个模型。

## 练习

1. 给缓存加过期时间：超过 N 秒的旧答案视为失效。
2. 用 capstone 的评测问题集运行一次 `offline_label()`，看便宜模型的真实通过率，再算一算路由能省多少钱。
3. 找一个规则版判断错、embedding 版判断对的问题，说明原因。

## 运行与边界

- 会调用真实模型并产生费用（缓存与路由演示各调用若干次）。
- 缓存没有考虑用户权限，多租户场景不能直接照搬；路由的准确率要用评测集验证（第 3 篇）。
