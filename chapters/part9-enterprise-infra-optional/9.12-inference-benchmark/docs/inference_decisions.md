# 推理性能决策卡

1. 固定模型、chat template、评测集、输入长度分布、并发、GPU 型号和服务版本。
2. 先跑 RAG/客服质量门禁；量化或换推理框架后，引用、拒答、工具调用和 JSON 均需回归。
3. 记录 TTFT、请求 p50/p95、输出 token/s、错误率、GPU 显存与总成本。
4. 权重显存不够时评估 BF16/FP8/INT8/INT4 的量化；这会影响权重大小和可能的质量。
5. 长上下文或高并发被 OOM 时评估 max model len、并发和 KV Cache 预算；KV Cache 是每个
   活跃序列的运行时状态，不是数据库缓存。FlashAttention 是更高效的注意力计算实现，可降低
   注意力阶段的内存/时间压力，但不能替代容量规划。
6. SLO 失败时按证据调整：缩短上下文、改检索、控制并发、换硬件/模型或做批处理；不要只靠
   提高超时。
