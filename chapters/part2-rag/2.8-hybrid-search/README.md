# 2.8 混合检索：同时照顾语义和精确词

[全书目录](../../README.md) · [上一章 2.7](../2.7-chunk-strategy/README.md) · [下一章 2.9](../2.9-query-rewrite/README.md)

- **目标**：把向量检索与 BM25 关键词检索合并成混合检索，弥补向量检索对专有名词的不足。
- **前置**：2.7；`rank_bm25`、`langchain-classic`。
- **环境**：离线，需要本地 embedding 模型。
- **命令**：`python tools/run_chapter.py 2.8`

## 问题

向量检索擅长语义相近，但对专有名词、编号、型号这类“必须精确匹配”的词常常不准：一个只出现一次、与上下文语义不相近的词，向量检索容易漏掉，而它往往正是用户要找的。

## 概念

- **BM25**：经典的关键词检索，按词频和文档长度打分，不依赖 embedding，与向量检索互补。
- **`EnsembleRetriever`**：按权重融合多个检索器的排名结果。`weights=[0.5, 0.5]` 表示各占一半；专有名词多的场景可以提高 BM25 的权重。
- **中文分词**：`BM25Retriever` 默认按空格分词，中文整句会被当成一个 token，检索直接失效。本章用字符 bigram 作 `preprocess_func`，生产中也可换成 jieba。混合检索会掩盖这种失效：向量那一路仍然有结果，所以要单独验证 BM25 一路。
- **迁移**：`EnsembleRetriever` 已从 `langchain.retrievers` 迁到 `langchain_classic.retrievers`。

## 流程

1. 切分长文章，建立向量检索器（`k=4`）。
2. 用 `_tok_zh` 分词，直接从片段建立 BM25 检索器（`k=4`）。
3. 用 `EnsembleRetriever` 融合两路。
4. 查询只含一个专有名词的问题 `Sharpe`（文章里只有一句提到它），分别打印纯向量和混合的召回结果，`★` 标出含有查询词的片段。

## 代码导读

[hybrid_search.py](hybrid_search.py)：重点看 `_tok_zh` 为什么必须给中文提供，以及 `EnsembleRetriever` 的权重；`show` 函数把两路结果并排打印。

## 练习

1. 把查询词换成文章里另一个只出现一次的词（如 `Obsidian`、`Milvus`），比较纯向量和混合的结果；再换成一个语义很明确的问题，观察差别是否消失。
2. 去掉 `preprocess_func`，单独调用 BM25 那一路，观察中文检索是否失效。
3. 把 `weights` 调成 `[0.8, 0.2]`，比较召回的变化。

## 运行与边界

- 混合检索是否更好，取决于领域里精确词的比重，要用评测集验证；上面的结果只是一个专门挑选的例子。
- 融合权重没有通用值，需要按文档和问题类型调整。
