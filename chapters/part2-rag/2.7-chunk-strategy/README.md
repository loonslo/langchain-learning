## 为什么做这个 gate

切分策略决定“一个完整事实能不能留在同一个片段里”。常见错误：

- 先按固定字数硬切，把“结论”和“理由”切开；
- 段落放得下也硬切，制造无意义边界；
- 单句超长时直接丢字，事实缺失；
- 产生空片段，污染索引；
- 只看块数，不看平均/最大长度和空块。

这个 gate 用固定文本验证“段落 → 句子 → 硬切”的优先级。

## 任务

实现 `gate/starter.py` 的两个函数：

| 函数 | 你要交付的行为 |
|---|---|
| `split_preserving_boundaries` | 空文本 `[]`；先段落、再句子、最后硬切；每段 ≤ `max_chars` |
| `chunk_stats` | 返回 count / avg_len / max_len / empty_count |

关键口径：

- `max_chars <= 0` -> `ValueError`。
- 段落用空行分隔；整段放得下就保留。
- 段落超长时按 `。！？!?` 切句；句子仍超长才硬切。
- 不产生空片段；输出顺序与原文一致。
- `chunk_stats` 空列表返回全 0。

## 概念地图

- **边界优先**：段落 > 句子 > 硬切；尽量让完整事实留在一块。
- **chunk_size**：成本与聚焦的权衡；太小断意，太大带噪声。
- **overlap**：缓解边界截断，但会增加重复和索引体积。
- **统计**：块数、平均/最大长度、空块，是切分质量的第一层检查。
- **单变量对比**：一次只改一个参数，才看得清影响。

## 边界

- gate 用固定文本和字符预算，不验证 embedding/召回质量。
- 通过 gate 只证明切分边界策略正确；哪种切法更好要用 2.9 的评测。
- 真实递归分隔符、overlap、多格式文档见参考实现。
