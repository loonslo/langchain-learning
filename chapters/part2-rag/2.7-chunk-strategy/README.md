# 2.7 切分策略：让完整事实留在片段里

[全书目录](../../README.md) · [上一章 2.6](../2.6-pdf-sources/README.md) · [下一章 2.8](../2.8-hybrid-search/README.md)

- **目标**：用同一个问题对比不同的切分参数，把“凭感觉设 `chunk_size`”变成“看效果调”。
- **前置**：2.2；本地 embedding 模型；`faiss-cpu`。
- **环境**：离线，不调用聊天模型。
- **命令**：`python tools/run_chapter.py 2.7`

## 问题

RAG 答得准不准，第一道关不是模型，而是文档切得好不好。切得太碎，一个完整的意思被劈成两半，检索只拿到半句；切得太大，一个块里塞了无关内容，噪声会淹没关键信息。

## 概念

- **`chunk_size`**：每块多大。小则精准但容易断意，大则完整但带噪声，也更费 token。
- **`chunk_overlap`**：相邻块重叠多少字，防止答案正好落在边界上；重叠过大则重复。
- **`separators`**：切分的优先级（段落 > 换行 > 句号 …），中文要自己配，见 `common.ZH_SEPARATORS`。
- **单变量对比**：每组参数只改一个变量，才看得清它的影响。

## 流程

1. 固定问题“LangGraph 最大的价值是什么”。答案“可控”在一句里，理由（普通 Agent 容易变成黑盒循环）在紧随其后的一句，最考验切分。
2. 依次用三组参数在长文章上切分、建库、检索：小块无重叠、小块有重叠、大块有重叠。
3. 每组打印块数、平均每块字数，以及召回的前 2 个片段。

## 代码导读

[chunk_strategy.py](chunk_strategy.py)：`STRATEGIES` 列出三组参数，`run_strategy` 完成“切分 → 建库 → 检索 → 打印”。embedding 模型只加载一次，因为变化的是切法，不是模型。文件末尾的注释解释怎样读结果。

## 练习

1. 运行后比较三组的召回：哪一组只召回了“结论”而没有“理由”？哪一组混进了无关的句子？
2. 把问题换成答案只在单句里的（如“MCP 的全称是什么”），看切法的影响是否变小。
3. 加一组“`chunk_size=500`、`overlap=0`”，观察召回里混进多少无关内容。

## 运行与边界

- 需要本地 embedding 模型，运行在本机，不产生模型费用。
- 中文 `chunk_size` 可从 300–500、overlap 取 10–20% 起步，再按评测调整；没有万能值。
- 只看几条召回结果不足以证明哪种切法更好，要用固定评测集量化（第 3 篇）。
