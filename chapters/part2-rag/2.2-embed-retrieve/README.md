## 为什么做这个 gate

向量检索最容易“看起来能跑”：

- 向量维度不一致，写入/查询时崩；
- 零向量导致除零或分数失真；
- 重复 ID 覆盖旧片段；
- `k=0` 或空索引没处理；
- 索引持有外部列表引用，外部一改分数就变。

这个 gate 用固定二维向量做确定性验收，不依赖 embedding 模型。

## 任务

实现 `gate/starter.py` 的三个部分：

| 部分 | 你要交付的行为 |
|---|---|
| `cosine` | 校验空/维度；零向量返回 0；返回 [-1,1] |
| `embed_texts` | 逐条向量化；校验类型/空向量/维度一致 |
| `VectorIndex` | `add` 校验 ID/维度/重复；`search` 按分数降序取 top-k |

关键口径：

- `cosine` 维度不一致、空向量 -> `ValueError`；零向量 -> `0.0`。
- `embed_texts` 空列表 -> `[]`；非字符串、空向量、维度不一致 -> `ValueError`。
- `add` 的 ids/vectors 长度一致；ID 非空且不重复；维度一致。
- `search` 的 `k < 1` -> `ValueError`；空索引 -> `[]`；查询维度不一致 -> `ValueError`。
- 索引内部保存向量副本，不持有外部列表引用。

## 概念地图

- **Embedding**：文本 → 固定维度向量；向量近表示语义近。
- **余弦相似度**：只看方向，不看长度；零向量没有方向。
- **向量索引**：存向量、找最近邻；内存索引程序退出即丢。
- **top-k**：k 是召回数量；太小漏，太大稀释。
- **分数不等于正确**：相似只是候选，答案质量要靠生成与评测。

## 边界

- gate 用二维假向量，不验证真实 embedding 的语义质量。
- 通过 gate 只证明向量/索引/排序结构正确。
- FAISS/Chroma 持久化见 2.10；混合检索见 2.8。
