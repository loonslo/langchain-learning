# 2.2 向量化与召回：先找到可能相关的片段

[全书目录](../../README.md) · [上一章 2.1](../2.1-load-split/README.md) · [下一章 2.3](../2.3-minimal-rag/README.md)

- **目标**：把片段变成向量存进 FAISS，用问题召回最相关的片段。
- **前置**：2.1；本地 embedding 模型（见根目录 README“准备本地 embedding 模型”）；`faiss-cpu`。
- **环境**：离线，不调用聊天模型。
- **命令**：`python tools/run_chapter.py 2.2`

## 问题

切好的片段不能靠关键词逐个比对：用户的说法和资料常常不同。需要一种按“意思相近”查找的方法，先拿到可能相关的候选，再决定怎么生成回答。

## 概念

- **Embedding**：把文本映射为固定维度的向量，向量越近语义越近。bge-small-zh 输出 512 维，与文本长短无关。
- **向量库（FAISS）**：不是数据库，而是“找最近邻”的索引，保存所有片段的向量。这里建在内存里，程序结束就没有了。
- **`similarity_search(问题, k)`**：把问题也转成向量，返回最相似的 k 个片段。k 太小可能漏掉相关片段，太大会带入无关内容。
- **相似不等于正确**：召回的只是“可能相关”的候选，能否回答问题要靠后续生成和评测判断。

## 流程

1. 复用 2.1 的做法读取并切分示例文档。
2. 加载本地 embedding 模型，查看一个片段被变成怎样的向量（维度、前 5 个数字）。
3. `FAISS.from_documents` 把所有片段向量化并存入索引。
4. 对三个问题分别 `similarity_search(k=3)`，打印召回的片段。

## 练习

1. 把 `k` 从 3 改成 1 和 6，观察召回的片段如何变化。
2. 对“怎么存储向量”这类不含原文关键词的问题，判断它能否命中讲 FAISS 的片段。
3. 用一个资料里完全没有的问题检索，观察它仍会返回 k 个片段：检索本身不会说“没有”。

## 运行与边界

- 需要本地 embedding 模型，路径来自 `common.EMBED_MODEL_PATH`；首次加载较慢。ModelScope 缓存目录里的点号会变成下划线（如 `bge-small-zh-v1___5`）。
- FAISS 只在内存里；要保存可用 `save_local`，或改用 Chroma（2.10）。
- 相似度分数没有天然的业务含义，不同模型的分数也不能直接套用同一个阈值。
