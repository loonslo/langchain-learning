# 2.6 PDF 与来源溯源：答案要能回到原文

[全书目录](../../README.md) · [上一章 2.5](../2.5-raw-sdk-rag-agent-loop/README.md) · [下一章 2.7](../2.7-chunk-strategy/README.md)

- **目标**：让 RAG 支持 txt 与 PDF，并在回答里标出处（文件名、页码）。
- **前置**：2.3。
- **环境**：调用真实模型，加本地 embedding 模型；读 PDF 需要 `pypdf`。
- **命令**：`python tools/run_chapter.py 2.6`（交互式：输入文件路径，直接回车使用示例文档）

## 问题

真实资料常是 PDF，用户也会追问“这个答案出自哪里”。基础 RAG 只能读一个 txt，没有来源信息，还容易出现“明明检索到了相关内容却说不知道”（过度拒答）。

## 概念

- **来源元数据**：每个片段带 `source`（文件名）和 `page`（页码）。切分时元数据会随片段保留，回答时才能标出处。
- **拒答与过度拒答**：本章的提示词是“有相关信息（哪怕只是部分）就尽量回答并标来源，完全无关才拒答”，比 2.3 的“没答案就说不知道”更不容易误拒，但也更容易越过证据，需要评测把关。
- **封装**：`load_document`、`build_retriever`、`build_rag_chain` 把建库和问答拆开。第 3 篇的评测脚本和 5.8 直接导入它们，把这条链当作被测对象。
- **扫描件**：没有文字层的 PDF，`extract_text` 返回空，该页会被跳过；全部为空时抛出错误。

## 流程

1. `load_document`：按扩展名读取 txt 或 PDF（逐页，跳过空页），每个 Document 带来源，PDF 还带页码。
2. `build_retriever`：切分（`chunk_size=300`、`overlap=50`）→ 向量化 → FAISS → 检索器（`k=4`）。
3. `build_rag_chain`：`format_docs` 把来源标签拼进上下文，提示词要求回答结尾用【来源】标注；`temperature=0`，让被评测时结果可复现。
4. 交互问答：输入问题，输出回答。

## 代码导读

[pdf_sources.py](pdf_sources.py)：先看 `load_document` 的 txt / pdf 分支，再看 `format_docs` 怎样把来源拼进上下文，最后看提示词里的两条规则。

## 练习

1. 用示例文档提问，检查回答是否带【来源】。
2. 找一份带页码的 PDF，问一个跨页的问题，看能否标对“第几页”。
3. 问一个资料外的问题，与 2.3 的拒答表现比较。

## 运行与边界

- 调用真实模型并产生费用；需要本地 embedding 模型。
- 模型标出的来源可能写错或编造，引用是否可信要另行核对（2.4 的引用检查、8.4）。
- 扫描件需要 OCR，本章不处理。
