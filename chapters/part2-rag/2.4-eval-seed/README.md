# 2.4 RAG 评测种子：从五个问题开始

[全书目录](../../README.md) · [上一章 2.3](../2.3-minimal-rag/README.md) · [下一章 2.5](../2.5-raw-sdk-rag-agent-loop/README.md)

- **目标**：用一小组固定样本建立评测口径，让后续每次改动（切分、召回、重排、提示词）都有可比较的起点。
- **前置**：2.3。
- **环境**：离线；检索和生成都是确定性替身，不调用 embedding 或 LLM。
- **命令**：`python tools/run_chapter.py 2.4`

## 问题

系统第一次答对时，容易认为它已经可用；再改一次切分或提示词，却可能让原先答对的问题变错。用一组固定问题保存预期，改动前后才有东西可比。

## 概念

- **评测样本**：同时描述问题、所需资料（期望片段）和预期的回答行为（关键词、是否应拒答）。期望片段和关键词是人工标注，不能从被测回答反推。
- **分项判断**：检索命中、关键词覆盖、引用、拒答分别判断，答错时才能定位到环节。
- **负例**：资料外的问题没有期望片段，不能按正例的召回口径评分。

## 数据与流程

示例用两条虚构的客服规则：来源 `refund.md`、`shipping.md`，片段 `refund-1`、`shipping-1`。`seed_cases.json` 有 5 个样本：单来源问答、另一来源、跨来源、资料外问题、空输入。

```text
样本 → 主题匹配的召回替身 → 去重与上下文预算
     → 有证据：原文拼接作答；无证据：拒答 → 分项判断
```

| 指标 | 规则 | 定位什么 |
|---|---|---|
| recall | 命中的期望片段数 / 期望片段总数（去重后）；无期望片段时为 `null` | 召回有没有找到必需资料 |
| keyword_ok | 所有标注关键词都出现在答案里 | 粗粒度的正确性 |
| refusal_ok | 实际拒答与样本要求一致 | 该答时答，该拒时拒 |
| citation_ok | 回答的引用覆盖期望片段且都来自上下文；拒答时没有引用 | 引用完整性与来源约束 |

关键词检查会被否定句或无关话术骗过，真实评测还要加人工复核或经过校准的裁判。来源 ID 存在，不等于事实被正确理解。

## 代码导读

[eval_seed.py](eval_seed.py) 依次读：`Chunk`（来源与片段标识）→ `retrieve` → `context`（按排名去重，整个片段放不下就跳过；预算用完时可能出现“召回成功但上下文为空”）→ `generate` → `evaluate`。样本在 [seed_cases.json](seed_cases.json)。无匹配主题视为低相关证据，不进入上下文。

对应的测试：`python -m pytest chapters/test_new_lessons.py -q`。

## 练习

1. 运行基线，删除一条必需的片段，观察哪一项先失败。
2. 只改引用标识（如换成 `fake`），解释为什么关键词仍可能通过而引用检查失败。
3. 做三次失败实验：重复首条规则（上下文只保留一次，不重复计入 recall）；把预算设为 0（recall 可以是 1，但系统拒答，样本失败）；用假引用替换真实引用（关键词可以通过，整体必须失败）。
4. 增加一个新样本：先写期望来源和拒答要求，再运行。不要只加“容易答对”的样本。

命令、分项结果与限制写进 [学习记录](workbook.md)。

## 运行与边界

- 通过只说明评测口径和替身闭环成立，不代表真实模型的 RAG 质量；真实检索与模型在 2.3 和第 3 篇接入。
- 真实 PDF、切分质量、语义相关度和生成忠实度都还没有验证。
