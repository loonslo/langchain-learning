# 2.3 最小 RAG：让回答依据检索资料

[全书目录](../../README.md) · [上一章 2.2](../2.2-embed-retrieve/README.md) · [下一章 2.4](../2.4-eval-seed/README.md)

- **目标**：把检索和生成串成完整的问答：基于检索到的资料回答，资料里没有就拒答。
- **前置**：2.2；`DEEPSEEK_API_KEY`。
- **环境**：调用真实模型，加本地 embedding 模型。
- **命令**：`python tools/run_chapter.py 2.3`

## 问题

检索能返回片段，但用户要的是答案。RAG 把问题和找到的资料一起交给模型，让它在给定证据内组织回答。此时要同时关注：资料找得对不对，回答有没有用到资料，没有资料时怎么办。

## 概念

- **RAG（检索增强生成）**：召回负责找候选；上下文拼接把候选整理成模型输入；生成负责组织文字；拒答处理证据不足。分开理解这些职责，答错时才知道先查哪一层。
- **retriever**：把向量库包装成可插拔的检索组件。`search_type="mmr"` 先粗取 `fetch_k` 条候选，再在相关性和多样性之间取舍，挑出 `k` 条，减少重复片段。
- **LCEL 的并行写法**：链开头的字典 `{"context": ..., "question": ...}` 让同一个问题同时走两条路：`retriever | format_docs` 得到上下文，`RunnablePassthrough()` 原样传下问题，两路汇成 prompt 的输入。
- **拒答指令**：prompt 要求“只根据上下文回答，没有就说不知道”，能抑制一部分幻觉，但不能保证。

## 流程

1. 读取、切分示例文档，向量化并建 FAISS（2.1、2.2 的合并）。
2. 构建 MMR 检索器（`k=3`、`fetch_k=10`、`lambda_mult=0.5`）。
3. `format_docs` 把召回片段拼成上下文，与问题一起填进 prompt。
4. 模型生成答案。共问四个问题：三个资料内的，一个资料外的（应拒答）。

## 练习

1. 运行后判断哪些回答有资料依据，资料外的问题是否被拒答。
2. 在提问循环里加一行 `retriever.invoke(q)` 并打印召回的片段，核对答案是否真的来自这些片段。
3. 把 `search_type` 改成默认的相似度检索，比较召回片段是否更重复。
4. 问一个条件不完整的问题，观察模型是拒答还是自行补全，记录它是否越过了证据。

## 运行与边界

- 调用真实模型并产生费用；需要本地 embedding 模型。
- “只依据资料回答”的提示词不能保证拒答；引用、空召回和上下文长度等边界要靠评测验证（2.4、第 3 篇）。
- 本章的回答不带来源；带来源的写法见 2.6。
