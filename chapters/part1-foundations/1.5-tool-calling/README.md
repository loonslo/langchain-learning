# 1.5 工具调用：由程序完成事实查询和计算

[全书目录](../../README.md) · [上一章 1.4](../1.4-context-memory/README.md) · [下一章 1.6](../1.6-mcp-intro/README.md)

- **目标**：让模型请求调用工具，由程序执行并把结果喂回，得到有事实依据的回答。
- **前置**：1.1。
- **环境**：调用真实模型。
- **命令**：`python tools/run_chapter.py 1.5`

## 问题

模型只会生成文字：大数运算容易算错，也查不到实时天气。要得到可靠结果，应由程序执行确定性的函数，模型只负责决定“调用哪个函数、传什么参数”。

## 概念

- **工具**：用 `@tool` 声明的函数。docstring 和参数类型会生成说明交给模型，模型据此判断用途；说明写得越清楚，选得越准。
- **`bind_tools`**：把工具清单绑给模型，模型回答时可以选择“请求调用某个工具”。
- **两轮流程**：第一轮模型返回 `tool_calls`（工具名和参数）；程序执行后用 `ToolMessage` 把结果追加回对话；第二轮模型基于真实结果给出最终回答。
- **判断依据**：是否要调用工具，看 `response.tool_calls` 是否为空，不看 `content`。
- **模型只是“请求”**：真正的执行、权限和副作用由程序控制。

## 流程

1. 用 `@tool` 定义 `get_weather` 和 `calculate`，`bind_tools` 绑给模型。
2. 第一轮：发送问题，读取模型返回的 `tool_calls`。
3. 逐个执行工具，用 `ToolMessage(tool_call_id=...)` 把结果放回消息列表。
4. 第二轮：再次调用模型，得到最终回答。

## 代码导读

[tool_calling.py](tool_calling.py)：先看两个工具的 docstring，再看第一轮返回的 `tool_calls`，最后看结果如何以 `ToolMessage` 回到对话。

## 练习

1. 先预测“北京天气怎么样？再帮我算 99 * 88”会产生几次工具调用，再运行验证。
2. 把 `get_weather` 的 docstring 改得含糊，观察模型选工具是否变差。
3. 问一个不需要工具的问题（如“你好”），确认 `tool_calls` 为空时直接看 `content`。

## 运行与边界

- 会调用真实模型并产生少量费用。
- 示例的 `calculate` 为了简短直接用 `eval`，会执行任意代码，不能用于真实项目；1.8 限制了可用名字，来自不可信输入的表达式应改用白名单解析（5.7）。
- 删除、转账、发信等有副作用的操作不能交给模型自由调用，需要确认与授权（4.11、4.12）。
