# 1.8 综合练习：会话与工具如何协作

[全书目录](../../README.md) · [上一章 1.7](../1.7-llm-internals/README.md) · [下一章 2.1](../../part2-rag/2.1-load-split/README.md)

- **目标**：把 LCEL 链、多轮记忆和工具调用拼成一个能用的命令行聊天机器人。
- **前置**：1.1、1.4、1.5。
- **环境**：调用真实模型，交互式运行。
- **命令**：`python tools/run_chapter.py 1.8`

## 问题

前几章的零件各自独立。真实应用要把它们接在一起：选一个角色，保存历史，需要计算时调用工具，退出时留下记录。本章不引入新概念，重点是体会零件怎样拼成整体。

## 概念

- **角色预设**：不同角色对应不同的 system 提示（Python 老师、计算器、自由聊天）。
- **历史与工具中间步骤**：历史只保存“用户输入 + 最终回答”，工具调用的中间消息不进入长期历史，上下文更简洁。
- **输入输出循环**：`while True` 读取输入，并处理 `clear`（清除记忆）、`quit`（保存并退出）等命令。

## 流程

1. `choose_role` 选择角色，得到名称和 system 提示。
2. 每一轮：`prompt.format_messages` 组合“system + 历史 + 本轮问题”，调用绑定了 `calculator` 的模型。
3. 若返回 `tool_calls`：执行工具、追加 `ToolMessage`，再调用一次模型得到最终回答；否则直接使用回答。
4. 把这一轮的用户输入和最终回答写入历史。
5. 输入 `quit` 时，`save_history` 把对话存成 `chat_<角色>_<时间>.txt`，写在本章目录（已被 `.gitignore` 忽略）。

## 练习

1. 选“计算器”角色，问“2 的 10 次方加 sqrt(16)”，观察是否触发工具。
2. 再加一个工具（如查询当前时间），看模型会不会在该用的时候调用。
3. 输入 `clear` 后追问前文内容，确认记忆已被清除。

## 运行与边界

- 会调用真实模型并产生费用；需要人工输入，不适合自动化测试。
- `calculator` 用 `eval` 并限制了可用名字，只是降低误用风险，不是安全沙箱；面向不可信输入应改用白名单解析（5.7）。
- 内存历史随程序退出丢失，只有 `quit` 时保存的文本可以复盘。
