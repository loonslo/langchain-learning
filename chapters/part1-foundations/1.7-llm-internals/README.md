# 1.7 LLM 原理认知：理解能力来源和边界

- **目标**：用小实验理解 token、embedding、attention 和幻觉，知道模型能力的来源与边界。
- **前置**：1.5。
- **环境**：需要本地 embedding 模型（见根目录 README“准备本地 embedding 模型”）；不调用聊天模型，不需要密钥。
- **命令**：`python tools/run_chapter.py 1.7`

## 问题

为什么模型能流畅回答，却也会编造不存在的事实？应用开发不需要训练模型，但需要分清“生成文字”和“查询事实”，这直接影响知识问答的设计与验收。

## 概念

- **Token**：模型处理文本的单位，计费和上下文长度都按 token 算。粗略地说，1 个汉字约 1–2 个 token，真实分词依赖各模型的 tokenizer。
- **Embedding**：把文本变成向量，语义越近向量越近，可用余弦相似度衡量。它是 RAG 检索的基础，2.2 起会用到。
- **Attention**：模型生成每个词时，按相关性关注前文的不同部分，所以能结合上下文。
- **幻觉**：模型本质是预测下一个最可能的 token，而不是查数据库；没见过准确信息时，仍可能流畅地编出看似合理的答案。RAG（提供真实上下文）和评测（量化幻觉率）正是为此存在。

## 流程

`llm_principles.py` 按四段依次演示，都是短小的认知实验：

1. token：打印一句话的字符数和粗略的 token 估算。
2. embedding：计算“狗 / 小狗”与“狗 / 股票”的余弦相似度，预期前者更高。
3. attention：一段文字说明，不涉及计算。
4. 幻觉：一段文字说明，不调用模型。

## 练习

1. 选两句意思接近但用词不同的话，再加一句无关的话，先预测三者的相似度排序，再运行验证。
2. 解释：为什么最高的相似度也不能证明它回答了问题？
3. 把示例文本换成英文或中英混合，观察相似度是否仍符合直觉。

## 运行与边界

- 需要本地 embedding 模型，可用环境变量 `EMBED_MODEL_PATH` 指定路径；首次加载较慢。
- token 数只是粗略估算，向量实验也不是对模型准确率的系统评估。
