# 1.2 控制输出：要求、随机性与流式回复

[全书目录](../../README.md) · [上一章 1.1](../1.1-first-call/README.md) · [下一章 1.3](../1.3-structured-output/README.md)

- **目标**：用 `temperature` 控制回答的随机性，用 `stream` 边生成边显示。
- **前置**：1.1。
- **环境**：调用真实模型。
- **命令**：`python tools/run_chapter.py 1.2`

## 问题

同一个问题，评测需要每次得到几乎相同的答案，写文案又希望有变化；用户等待长回答时，也不该面对一片空白。这两件事分别由 `temperature` 和流式输出控制。

## 概念

- **temperature**：回答的随机性。为 0 时同一问题几乎每次相同，适合评测、抽取、分类；较高时更发散，适合文案。它只改变取样的随机程度，不保证事实正确。
- **`invoke` 与 `stream`**：`invoke` 等全部生成完再一次返回；`stream` 返回生成器，模型每产出一段就交给程序，界面据此逐字显示。
- **要求和参数分开写**：对输出的要求（角色、口吻）写在 system 消息里；`temperature` 是模型客户端的参数，两者控制的东西不同。

## 流程

1. 用同一个 prompt、同一个问题，分别创建 `temperature=0` 和 `temperature=1` 的模型各问一次，对比回答。
2. 用 `chain.stream(...)` 取得回答片段并逐段打印（`end=""` 不换行，`flush=True` 立即刷新）。

## 练习

1. 把 `temperature=0` 的调用连跑 3 遍，判断是否几乎一字不差；再对 `1.0` 做同样的对比。
2. 给 `stream` 换一个更长的问题，比较逐字显示与一次性返回的等待体验。
3. 记录观察到的差异。`temperature=0` 仍可能出现细微差别，不要把“几乎一致”当成“绝对一致”。

## 运行与边界

- 会调用真实模型并产生少量费用。
- `temperature=0` 提高可复现性，但不同模型版本或服务端实现仍可能有差异。
