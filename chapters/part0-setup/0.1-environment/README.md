# 0.1 环境与离线自检

[全书目录](../../README.md) · [下一章 0.2](../0.2-learning-workflow/README.md)

- **目标**：说清“代码由哪个 Python 执行、依赖装在哪里、密钥从哪里读”。
- **前置**：无。
- **环境**：离线，不连接模型，不下载权重，不显示凭据。
- **命令**：`python tools/run_chapter.py 0.1`

## 问题

初学时容易把环境问题误认为代码写错：解释器不是项目的解释器，依赖装在另一个环境，模型配置尚未准备好。先把这些问题分开，得到一张可以反复核对的起点清单。

## 概念

- **解释器**：执行 Python 的程序。仓库默认 Python 3.14，脚本最低要求 3.11；项目或 CI 明确声明其他版本时以声明为准（当前 CI 用 3.11）。
- **虚拟环境**：把本项目的依赖放在独立位置。IDE 和终端可能各用一个解释器，先确认二者一致。
- **环境变量与 `.env`**：提供运行配置，如 `DEEPSEEK_API_KEY`。文件存在只说明有这个文件，不说明密钥有效或服务可连。

## 流程

1. 确认仓库根目录与当前解释器。
2. 检查课程依赖能否导入，按“从哪一篇开始需要”分组。
3. 检查配置是否存在，只输出布尔值，不调用模型。

## 搭建环境

从仓库根目录执行（PowerShell）：

```powershell
# 仅在还没有虚拟环境时创建
uv venv --python 3.14
# 安装课程依赖
.\.venv\Scripts\python.exe -m pip install -r requirements-course.txt
# 自检
.\.venv\Scripts\python.exe tools/run_chapter.py 0.1
```

macOS / Linux 使用 `.venv/bin/python`。已有 `.venv` 时直接使用，不重建。旗舰项目里用 `uv sync` 创建的环境按各自的 `pyproject.toml` 安装依赖，不要与根目录环境混用。

需要真实调用模型时，从根目录 `.env.example` 复制出 `.env`，只填自己的配置；第 0–6 篇只需 `DEEPSEEK_API_KEY`，其余变量供 capstone 使用。密钥和 `.env` 不进入 Git，也不贴进学习记录。

## 代码导读

[check_environment.py](check_environment.py)：

- `REQUIRED_GROUPS`、`OPTIONAL_GROUPS`：依赖按篇分组，写的是 import 名（`faiss-cpu` 的导入名是 `faiss`）。必需组缺失时退出码为 1，可选组缺失只报告。
- `find_spec` 只查模块是否已安装，不导入，也不检查版本。
- 密钥只输出布尔值：`.env` 是否有非空值、进程环境是否设置。

## 练习

1. 运行自检，记录解释器版本、退出码和缺失依赖，并与 IDE 里配置的解释器路径对照。
2. 缺依赖时补装对应的包，再运行一次，确认该组的缺失列表清空。
3. 建立 `.env` 后再自检，确认密钥被识别，且没有出现在输出里。

回答：为什么 IDE 与终端有时使用不同的解释器？为什么自检通过仍不能证明模型可用？把结论写进 [学习记录](workbook.md)。

## 边界

通过只说明环境可检查。模型下载、API 账号、网络连通和业务功能都没有验证。下一章学习如何保存这些证据。
