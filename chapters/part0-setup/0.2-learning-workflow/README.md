# 0.2 学习方法与验收记录

[全书目录](../../README.md) · [上一章 0.1](../0.1-environment/README.md) · [下一章 1.1](../../part1-foundations/1.1-first-call/README.md)

- **目标**：每章结束时留下“我改了什么、哪条证据证明它、还不能证明什么”。
- **前置**：0.1。
- **环境**：无需运行代码。

## 问题

读懂一个脚本，和能独立完成一个功能之间还有距离。你可以复述 RAG 的定义，却说不清答错时该先查检索还是生成。本章建立一种记录方式，让每章都留下自己的理解和可定位的证据。

## 概念

- **问题**：这个功能为什么存在。
- **流程**：数据依次经过哪些步骤。
- **验收**：能证明行为的观察或测试。教程里的完成版代码只是参考实现，个人是否学会由自己的练习和结果决定。

## 一次练习的六步

1. 从 [章节总地图](../../README.md) 选一章，先读目标、输入与失败边界。
2. 沿正式入口画出调用链：输入 → 数据 / 模型 / 工具 → 输出，不要只看新增文件。
3. 先运行已有例子或相关测试，记录基线与执行环境。
4. 提出一个可验证的假设，只改一处实现或输入，再观察结果。
5. 加一个有意义的失败实验，证明系统知道何时拒答、失败或停止。
6. 保存命令、退出码、证据位置与限制，再更新任务状态。

不同主题要观察的对象不同：

- RAG：来源、切分、召回、重排、上下文、生成、引用，分别观察。
- Agent：状态、节点、边、工具副作用、最大步数、终止原因。
- 测试替身固定输出，适合验证业务规则；真实模型评测还要关注样本、版本、质量和成本。

## 三条运行路线

| 路线 | 从哪里运行 | 证明什么 |
|---|---|---|
| 独立章节 | 根目录 `python tools/run_chapter.py 2.4` | 这一节的局部规则与输出 |
| 旗舰项目教学快照 | `tools/materialize.py` 还原后，运行累计测试 | 当前步骤与此前能力的集成 |
| capstone 整合实现 | 根目录 `python -m pytest capstone/test_production.py -q` | capstone 的离线生产边界 |

旗舰项目快照和 capstone 入口不同，一套通过的测试不能替另一套背书。真实模型回归见 `capstone/test_regression.py`，运行前确认本机配置、评测资料和外部调用范围。

## 练习：做一份可复查的记录

1. 运行 0.1 自检，把结果写进 [学习记录](workbook.md) 作为基线。
2. 提出假设：“错误引用应该被拒绝”。到 2.4 时，删去引用或改成不存在的片段 ID，确认引用检查失败，同时观察答案关键词仍可能通过。
3. 记录里不写密钥、token 或真实客户数据；不因为目录存在就写“已完成”。

## 验收

另一位读者只凭你的记录就能重跑实验，并区分观察到的事实和推测的原因。回答：哪条测试覆盖失败路径？哪一项仍需要真实模型？出问题时如何恢复自己的修改？

## 边界

模板只是记录工具，内容要靠实际运行填写。课程文件存在，不代表你已学完；离线测试通过，也不能代替真实模型或部署验收。
