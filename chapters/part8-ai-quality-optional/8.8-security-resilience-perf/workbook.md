# 章节 8.8 工作簿 · 安全、韧性与性能

## 0. 变更闭环

| 文件 | 状态 | 它接到哪个旧能力 |
|---|---|---|
| `src/ai_testing/resilience.py` | 新增 | 为旗舰后端（7.8 / step2）API 和 8.7 的 E2E 连接点提供故障与性能策略 |
| `tests/test_resilience.py` | 新增 | 防止无限重试、输入越界和 SLO 误判 |

## 1. 思考

1. 为什么重试次数必须是硬上限？
2. p95 通过但 error rate 超标时，系统能否发布？
3. 控制字符检查和提示词注入检测分别属于什么边界？

## 2. 验收

- [ ] 失败操作最多执行 max_attempts 次。
- [ ] 输入长度和控制字符有明确失败结果。
- [ ] 延迟或错误率任一超标，SLO 失败关闭。

## 3. 本章结论

韧性不是“尽量重试”，而是在可控预算内恢复，并在超过预算时快速、可观测地失败。
