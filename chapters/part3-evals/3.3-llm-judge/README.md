# 3.3 LLM 评委：让语义判断也能被复查

[全书目录](../../README.md) · [上一章 3.2](../3.2-eval-basics/README.md) · [下一章 3.4](../3.4-eval-dataset-build/README.md)

- **目标**：用另一次 LLM 调用当裁判，评“答案正确性”和“忠实度”，并了解裁判本身的局限。
- **前置**：1.3（结构化输出）、2.6、3.2；`DEEPSEEK_API_KEY`；本地 embedding 模型。
- **环境**：调用真实模型。
- **命令**：`python tools/run_chapter.py 3.3`

## 问题

3.2 的关键词匹配太死板：答案写“检索增强生成”，标准答案写“检索+生成”，意思一样却判为没命中。更接近人的判断的做法，是让另一次 LLM 调用给答案打分。

## 概念

- **答案正确性**：和标准答案比，意思对不对，不纠结用词。
- **忠实度（faithfulness）**：答案是否只依据给定上下文，有没有编造。这是防幻觉的关键指标。
- **结构化裁决**：用 `Verdict`（分数 + 理由）和 `with_structured_output` 让裁判返回结构化结果，可统计、可追溯。
- **裁判也会错**：LLM 裁判有偏好（比如偏爱长答案），分数是参考，不是真理。重要结论要抽样人工复核，裁判模型最好比被评模型更强。裁判怎样校准见 8.5。

## 流程

1. 读评测集里“非拒答且有标准答案”的题（`eval_set_full.json`，没有则用内置 2 条）。
2. 对每题：RAG 链回答一次 → `judge_correctness` 对比标准答案 → 取召回的上下文，`judge_faithfulness` 判断是否忠于上下文。每题共调用 3 次模型。
3. 打印每题两个 1–5 分及理由，最后输出平均正确性。

## 代码导读

[llm_judge.py](llm_judge.py)：先看 `Verdict` 和裁判提示词（评分标准怎么写），再看两个 `judge_*` 函数的区别：正确性对照标准答案，忠实度对照召回上下文。

## 练习

1. 故意构造一个“听起来对、其实是编的”答案，看忠实度裁判能否抓出来。
2. 把同一个答案交给裁判多次，观察分数是否稳定。
3. 比较 3.2 判为“未命中”而 3.3 判为“正确”的题，理解语义判断与关键词判断的差别。

## 运行与边界

- 每题调用 3 次模型，费用约为 3.2 的三倍。
- 裁判分数不能替代来源、权限和引用边界的检查。
