# 3.2 基础评测：把预期拆成可以判断的项

[全书目录](../../README.md) · [上一章 3.1](../3.1-error-analysis/README.md) · [下一章 3.3](../3.3-llm-judge/README.md)

- **目标**：手写两个可解释的评测指标：拒答正确率和关键词命中率，并把评测集放进 JSON 文件共用。
- **前置**：2.6（复用它的检索与问答链）；`DEEPSEEK_API_KEY`；本地 embedding 模型。
- **环境**：调用真实模型。
- **命令**：`python tools/run_chapter.py 3.2`

## 问题

“准确率提升了”，提升多少？靠什么算的？说不出来就是没有评测。先用最简单、最容易解释的指标，把“感觉还行”变成带分母的数字。

## 概念

- **拒答正确率**：文档里没有答案的问题，模型有没有说“不知道”。这是防幻觉的底线。判断规则是回答里出现 `REFUSE_HINTS` 中的任意词。
- **关键词命中率**：标准答案的核心词是否都出现在回答里。只评有关键词的题；引用题没有关键词，跳过。
- **带分母**：每个指标都写成 “X/Y = Z%”，才能核对。
- **评测集与代码分离**：评测集从 `chapters/shared-data/eval_set_full.json` 读取，3.4、3.5 生成，3.3、3.6、3.7 共用，改一处全线生效。找不到时退回内置的 4 条示范题，本章仍可运行。
- **局限**：关键词完全匹配太死板，同义不同词会误判。3.3 用 LLM 裁判解决。

## 流程

1. `load_eval_set` 依次找 `eval_set_full.json`、`eval_set.json`，都没有就用内置示范集。
2. 复用 2.6 的 `build_retriever` 和 `build_rag_chain` 得到被测的 RAG 链（`temperature=0`）。
3. `evaluate` 逐题调用：应拒答的题统计拒答是否正确，应回答的题统计关键词是否都命中。
4. 打印带分母的两个指标。

## 代码导读

[eval_basics.py](eval_basics.py)：先看 `INLINE_DEMO` 与 `load_eval_set`（评测集从哪来），再看 `looks_like_refuse`，最后看 `evaluate` 里两类题的分支。

## 练习

1. 先用内置示范集运行，记录两个指标；再运行 3.4、3.5 生成完整评测集，回来重新运行，比较 25 条的结果。
2. 找一条被判“乱答”或“未命中”的题，判断是系统错了，还是判断规则太死板。
3. 往 `REFUSE_HINTS` 里加一种拒答说法，看结果如何变化。

## 运行与边界

- 调用真实模型并产生费用。关键词规则会漏判同义表达，也会被否定句骗过。
- 拒答判断依赖固定短语，模型换一种说法就会误判。
- 分数只在同一评测集、同一版本下比较才有意义。
