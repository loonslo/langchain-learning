# 3.1 失败分析：先找到最早出错的环节

[全书目录](../../README.md) · [上一章 2.11](../../part2-rag/2.11-multimodal-rerank/README.md) · [下一章 3.2](../3.2-eval-basics/README.md)

- **目标**：看到错误答案时，用事实把症状、直接原因和根本原因分开，找到最早出错的环节。
- **前置**：2.4。
- **环境**：离线。
- **命令**：`python tools/run_chapter.py 3.1`

## 问题

错误答案只是症状。证据没进入上下文可能是直接原因，资料没同步或权限过滤异常才可能是根本原因。只看最终答案就动手改提示词，往往改错了层。

## 概念

`Trace` 是一条简化的、人工标注的诊断记录：资料是否存在、事实是否被切分保留、期望片段，以及召回、重排、上下文和引用的片段 ID。`answer_correct` 是评测标签，不是脚本自动理解答案得到的结论。

```text
来源 → 切分 → 召回 → 重排 → 上下文 → 生成 → 引用
             每一步都保留可比对的片段标识
```

`diagnose` 按管线顺序报告最先失败的已记录环节，下游可能还有别的问题。

| 已观察事实 | 定位 | 下一步检查 |
|---|---|---|
| 原始资料不可用 | source | 数据版本、同步、访问权限 |
| 切分后事实不完整 | chunking | 限定条件、段落与重叠 |
| 期望片段没召回 | retrieval | 查询、过滤、向量模型 |
| 召回有、排序截断后没了 | reranking | 排序分数、阈值、top-k |
| 排序有、上下文没了 | context | 去重、拼接、预算 |
| 证据齐全但答案错或误拒答 | generation | 提示词、模型、答案标签 |
| 答案正确但来源错误 | citation | 输出 schema、来源映射 |

资料外问题单独看拒答和有无引用；资料内样本必须先有预期片段的标签。诊断字段缺失时，补日志或补标签，不把未知事实填成成功。

## 代码导读

[error_analysis.py](error_analysis.py)：先看 `Trace` 各字段的默认值（默认表示“该环节正常”），再看 `diagnose` 里检查的顺序：拒答样本 → 标签 → 来源 → 切分 → 召回/重排/上下文 → 生成 → 引用。默认展示三个案例：通过、上下文丢失、答案错误。

对应的测试：`python -m pytest chapters/test_new_lessons.py -q`。

## 练习

1. 构造两份错误答案相同的记录：一份没有召回证据，一份有证据却答错。运行诊断，解释为什么症状相同而建议修复的层不同。
2. 先删掉 `retrieved_ids`，再恢复它并删掉 `context_ids`，比较输出。
3. 同时设置“召回失败”和“答案错”，确认先报告召回问题。
4. 对真实的 bad case，保存样本 ID、数据版本、配置、request_id 和片段标识；私有问题和凭据不直接入库。先用最小修复验证一个假设，再扩展调整，并用原样本和相邻的失败样本回归。

在 [学习记录](workbook.md) 写一条“观察事实 → 待验证假设 → 最小实验 → 结果”。

## 运行与边界

- 示例是依据显式记录执行的确定性规则；真实系统需要可靠的日志和人工复核，不能只凭最终答案猜过程。
- 来源缺失要继续检查同步、版本和权限，不能因为脚本输出 `source` 就断言一定是连接器的问题。
- 本例没有追踪真实模型、延迟或成本；评测基线和 LangSmith 在后面的章节补充这些证据。
