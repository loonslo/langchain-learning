# 合并说明：给 ai-transition-diary 加一张「代码对照解读卡」

## 这次改了什么

你 Day30 / Day31 那种图更好懂，是因为它们做了现在 skill 明令**禁止**的一件事：把**真实代码**放进图里，再逐行标出「这行代码 ↔ 它干嘛」，配上流程图和一句结论。现在的 skill 只会出无代码的流程框/管线/对比卡，所以缺了这层「看着代码理解」的桥。

这次新增**一张、且仅此一张**允许出现源代码的卡：**代码对照解读卡（code-explain card）**。它把四块拼在一张图里：

1. **两段代码 = 等价对比**（Day30 的「手搭版 = 一行版」，中间一个大等号）
2. **对应关系（彩点映射）**：每行代码 / token 用彩色圆点 ↔ 一句大白话
3. **流程图**：方框 + 判断菱形 + 循环回边，展示代码运行时在干嘛
4. **结论横幅**：底部一条黄色高亮的一句话结论

其余所有卡（封面 / 定位 / 前后对比 / 方法 / 关键知识点）**保持无代码**，规则不变。这张卡是**加法**，不是替换。

> 按你的选择：竖版为主 + 横版可选；只新增这一种卡；吸收了「对应关系彩点映射」「两段代码=等价对比」「结论横幅」三块（未加 Day31 底部的面试话术/动手练习）。

看效果：同目录下 `sample_day30_wide.png`（横版·两段代码等价对比）和 `sample_vertical.png`（竖版·一段代码逐行拆解），都是这张新卡渲染出来的。

### 4) 新增一整段（放在 Generate And Verify Images 列表之后）

```md
### 代码对照解读卡 (Code-Explain Card) — the one card that shows code

有些天，最好懂的解释就是代码本身 + 每行在干嘛。为此新增这张、且仅此一张允许出现源代码的卡，把「精简真实代码 + 对应关系 + 底层流程 + 一句结论」拼在一起，比纯流程框更直观。它是加法，不替换任何无代码卡。

**什么时候用（可选，每天最多一张）：** 当天主线用「看代码 + 看含义」讲最清楚时——两种写法等价对比、一段关键代码逐行拆解、一个封装展开成底层流程。如果流程卡/分支循环卡已经把机制讲透了，就不出这张，别硬往每天塞代码。

**四个模块（除 code_blocks 外都可选）：**
- **两段代码 = 等价对比**：给两个 `code_blocks` 并设 `equals: true`，渲染成并排 + 大等号（Day30）。只给一段就竖向单框。
- **对应关系（彩点映射）**：`mapping.rows`，每行是 code token → 一句大白话，前面一个彩色圆点。只要图里出现了代码，就配上它——这是让新手看懂代码的关键。
- **流程图**：可选 `flow`（方框 + 一个判断菱形 + 循环回边），展示代码运行时在干嘛。
- **结论横幅**：一句 `conclusion`，渲染成底部黄色横幅（Day30 的「create_react_agent 只是帮你提前把那张图搭好了」）。

**画幅：** 默认竖版 3:4（`"layout": "single"`）。两段代码并排对比时用 `"layout": "wide"`（4:3，左流程 / 右对应关系）。节点标签保持一行短词，代码只留关键几行——卡塞太满 bounds 审计会报越界/触底，那是提示你精简，不是去放大画布。

**Fade / highlight 照旧看今昨代码差异：** 给某个 code block 或 flow 节点 `"kind": "now"`（accent + 可选 `今天重点`/`今天新增` 标签）或 `"kind": "fade"`（灰，沿用）。这张卡信息密，flow 节点的沿用用颜色表达即可，小标签可省，避免拥挤。

**D-dict 结构（在 `D` 里加一个可选列表 `code_explain`）：** 见 `scripts/render_cards_template.py` 里 `D` 末尾的注释示例，或本次交付的 `合并说明` 附带示例。渲染器会把 `code_explain` 卡排在方法卡之后、关键知识点卡之前，关键知识点仍是最后一张。
```

## code_explain 的完整字段速查

```python
"code_explain": [
  {
    "layout": "wide",             # "single"(竖版3:4,默认) | "wide"(横版4:3,两段代码并排)
    "title": "为什么这两个写法本质上一样?",
    "subtitle": "手搭 ReAct Agent vs create_react_agent 一行版",   # 可选
    "equals": True,               # 两个 code_blocks 间画大等号（并排对比）
    "code_blocks": [              # 1 段=竖向单框；2 段+equals=并排对比
      {"label": "手搭版（自己搭图）",
       "kind": "plain",           # plain | now(今天重点) | fade(沿用)
       "tag": "今天重点",          # 可选，覆盖默认标签
       "lines": ["llm_with_tools = llm.bind_tools(TOOLS)",
                 "g.add_conditional_edges(\"agent\", tools_condition)"],
       "caption": "显式把每个节点和边都写出来"},   # 可选，框下一句
      {"label": "一行版（官方封装）", "kind": "plain",
       "lines": ["create_react_agent(", "    tools=TOOLS,", ")"],
       "caption": "把同样的骨架提前封装好了"},
    ],
    "flow": {                     # 可选
      "note": "模型接收 messages，可能直接回答，也可能要求调工具",  # 可选气泡
      "nodes": [
        {"id": "start", "label": "START", "kind": "plain"},
        {"id": "agent", "label": "agent 节点", "kind": "now"},
        {"id": "cond",  "label": "有 tool_calls?", "shape": "decision"},
        {"id": "end",   "label": "END", "kind": "plain"},
        {"id": "tools", "label": "tools 执行", "row": 1, "under": "cond"},
      ],
      "edges": [                  # (from, to, label, loopback)
        ("start","agent","",False), ("agent","cond","",False),
        ("cond","end","否",False), ("cond","tools","是",False),
        ("tools","agent","结果带回，再想一轮",True),
      ],
    },
    "mapping": {                  # 可选，但只要有代码就强烈建议配
      "title": "对应关系",
      "rows": [
        {"code": "bind_tools(TOOLS)", "meaning": "让模型知道可用工具", "ci": 0},
        {"code": "tools_condition",   "meaning": "判断是否继续调用工具", "ci": 2},
      ],                          # ci: 圆点/代码配色索引 0=蓝 1=青绿 2=绿
    },
    "conclusion": "create_react_agent 不是另一种 Agent，而是把手搭版那张图帮你提前搭好了。",
  }
]
```

**小抄：**
- 节点 `label` 不要放 `\n`（换行由渲染器按宽度自动折），保持一行短词最稳。
- 判断点加 `"shape": "decision"` 渲染成菱形；`"row": 1` + `"under": "某节点id"` 把它画在主链下方（如 ReAct 的 tools）。
- 代码只留能说明问题的几行；卡塞满会 bounds 报错，那是让你精简的信号。
- 运行：把渲染器复制进当天 `dayN/`，`OUTDIR=<dayN> python render_cards_template.py`。
