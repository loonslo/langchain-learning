# Day79 打卡 · 前端对接

## 今天解决的业务问题

Day78 已经具备客服 API，但用户只能通过终端或 Swagger 观察结果。Day79 增加独立前端工作台，把后端能力变成可操作、可讲解的演示项目。

## 前后端边界

| 前端职责 | Day78 后端职责 |
|---|---|
| 输入问题、会话切换、展示 loading | JWT 校验、会话隔离、统一业务编排 |
| 展示答案、来源和工单编号 | RAG 检索、拒答、订单工具、人工升级 |
| 保存 token、展示连接状态 | 签名身份、幂等、反馈审查队列 |
| 发送正负反馈 | 校验反馈并决定是否进入 review queue |

## 真实调用链

```text
Day79 Vite 页面
  → /api 代理
  → Day78 /chat
  → TokenVerifier
  → SyncingApplication
  → SupportApplication
  → RAG / Order Tool / Ticket
  → ChatResponse
  → 页面来源与反馈区域
```

## 今日验收记录

- [ ] 未连接 token 时，页面阻止发送并提示身份配置。
- [ ] 合法 token 能完成 FAQ 问答并显示 `refund.md` 等来源。
- [ ] 连续发送短追问，后端会使用同一 `session_id`。
- [ ] 订单号沿请求传入 `order_id`，不由前端伪造订单结果。
- [ ] 反馈请求命中 Day78 `/feedback`，负反馈可进入审查队列。
- [ ] 错误 token 收到 401 后，页面清除本地 token。

## 当前证据能证明什么

- 前端页面和 Day78 HTTP 契约已经接通。
- 页面展示的回答、来源、订单结果和工单编号来自后端响应。
- 前端没有绕过 JWT 自报用户身份。

## 当前仍不能证明什么

- 前端生产部署的 HTTPS、域名、反向代理和 CSP 配置。
- 浏览器端 token 存储策略已经满足生产安全要求；当前仅用于本地演示。
- Day78 的真实模型、向量模型和上游订单系统在所有环境都可用。
