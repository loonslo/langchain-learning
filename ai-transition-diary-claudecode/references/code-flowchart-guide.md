# 代码流程图解指南 (Code Flowchart Guide)

`SKILL.md` 的横版代码流程图规则以本文件为准。每次执行 `ai-transition-diary` 都必须生成横版流程图，不能因为当天代码较短、没有循环，或竖版已经有源码结构图就跳过。

- **竖版学习卡**（`render_cards_template.py`）：3:4，讲“今天新增补在哪、为什么有用”。
- **横版代码流程图**（`render_flowchart_template.py`）：1560×1075，展开当天 changed/new 代码的真实执行路径，给想顺着源码读的人。

## 每次必须生成什么

- 最少 1 张，通常 1–4 张。
- 一张图只讲一个有意义的函数或一条独立执行路径。
- 有分支、循环、重试、工具调用、降级、异常出口时，必须如实画出。
- 没有分支时，仍要画真实线性路径：输入 → 关键处理/API → 输出。
- 多个小函数共同完成同一条路径时，可以合成一张端到端图；不要给 import、配置赋值、简单 getter/setter 或未变化的初始化单独出图。
- 只从当天 `changed` / `new` 代码选题，不能拿 reused 代码凑数量。

选择顺序：

1. 先找决定运行方向的图构建函数、agent 主循环或入口函数。
2. 再找有独立分支/循环/错误处理的 changed/new 函数。
3. 如果前两项都没有，画当天主功能的线性端到端调用链。

## 每张图的固定构成

1. **标题**：`函数名() 流程图 · 一句话主题`。标题必须动态换行并保持在顶部安全区，不能压住主流程节点。
2. **主流程**：使用真实节点、函数或 API 名。
   - `pill`：入口/出口；绿=入口/正常出口，红=失败/结束出口。
   - `box`：普通步骤蓝色，工具节点紫色，降级节点橙色。
   - `diamond`：条件判断黄色，写判断依据本身；主标题和副标题都必须落在菱形实际内区，不能只按外接矩形判断。
3. **边**：箭头贴节点边界；分支边标短 `是/否`，完整含义放流程说明；回边用 `via` 折点绕行。任何箭头都不能穿过无关节点、标题、标签或下方面板。
4. **图例**：最底部整条横向图例，解释形状和颜色。
5. **流程说明**：左下编号 1..n，按实际运行顺序讲清每一步。
6. **循环示意 / 核心要点**：右下面板。有回环时画小循环和真实轨迹；无回环时放核心要点或真实示例。
7. **账号签名**：每张图右上或右下保留淡色 `@测试阿甲`，不得与标题、节点、图例重叠。
8. **无源码块**：只放节点、箭头和短标签。允许真实 API 名和一个短调用签名，禁止多行实现代码。

## 数据驱动生成

使用 [../scripts/render_flowchart_template.py](../scripts/render_flowchart_template.py)。复制到 `dayN/` 并命名为 `render_dayN_flowcharts.py`，只编辑底部 `DAY` / `DATE` / `SCENES` 数据。

每个 scene 包含：

- `name`：`{DATE}-AI-Day{DAY}-flow-1-<函数名>`。
- `title`：函数/API + 一句话主题。
- `legend`：`[(形状, 调色板, 文字), ...]`。
- `nodes`：`{id: {x,y,w,h,shape,pal,title,sub?,r?}}`。
- `edges`：`[{a,b,label?,lcol?,via?,lx?,ly?}]`。
- `notes`：可选的短注记框。
- `flow`：编号流程说明。
- `side`：`loop` 或 `note` 面板。

运行：

```text
OUTDIR=<dayN> python render_dayN_flowcharts.py
```

脚本必须为每个 scene 运行边界与碰撞审计并采用“失败即停止”：标题超宽、顶部节点侵入标题区、菱形文字出界、边标签撞节点/箭头、箭头穿无关节点、下方面板溢出时都要直接报错。修正 `SCENES` 后重跑，不能关闭审计来出图。

## 布局硬规则

- 顶部标题区和主流程区必须分开。主流程节点不得进入标题实占区域，长标题动态换行后要自动增加净空。
- 主流程通常放在标题下方、下方面板上方；图例固定在最底部。
- 边先画、节点后画；但审计按完整几何关系进行，不能用绘制顺序掩盖穿透。
- 标签优先写短 `是/否`；长解释移到编号面板。标签背景留白不能覆盖节点边框或另一条箭头。
- 菱形文字按每一行所在高度计算可用宽度；副标题过长时缩短展示文案、扩大菱形或改放编号面板。
- 左右下面板内的文字、循环轨迹和小卡必须按实际字体测量；内容过多时先换行或减少卡片，不能溢出面板底边。
- `@测试阿甲` 放在安全角落并参与碰撞审计。

## 终检与正式顺序

1. 先看联络单，快速核对全套图的主题和数量。
2. 再逐张打开原尺寸 PNG，检查标题四周、每个菱形、分支标签、回边、左右下面板和图例。联络单不能替代逐张检查。
3. 确认节点/分支来自真实源码，签名存在且不抢内容。
4. 草稿里的正式图片顺序固定为：竖版内容卡（先不放 glossary）→ 横版流程图 → glossary 最后一张。联络单仅用于 QA，不列为发布图片。

## 和竖版卡片的关系

横版流程图是每次都要追加的代码结构层，不替代封面、定位图、前后对比图、竖版源码结构图解和最终知识点卡。

如果某张竖版方法卡会和横版图重复，可以省略这张方法卡；但横版流程图本身不能省略。竖版负责“是什么、为什么、补在哪”，横版负责“真实代码怎么从入口走到出口”。
