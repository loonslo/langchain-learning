LangGraph 心智模型

把流程建模成「状态图」

一句话洞察：LangGraph 用状态图描述 Agent 流程——线性场景等价于 LCEL，真正价值在分支、循环与持久化状态。

LangGraph 把流程建模成状态图：State 是贯穿全程的数据，Node 读写 State，Edge 定顺序。 线性场景它等价于 LCEL，真正价值在能表达分支、循环和持久化状态。
一 · 三个核心要素

State贯穿全程的数据

一张图共享的「黑板」。所有节点都能读、都能改，是整个流程的单一数据源。

TypedDict / MessagesState 单点真相 随步骤累积

Node读写 State

真正的计算单元：LLM 调用、工具执行、检索、判断……输入是 State，产出是 State 的增量更新。

agent / tools planner / reviewer 纯函数返回 dict

Edge定顺序

节点间的连线，决定「谁先谁后」。普通边定线性顺序，条件边做分支路由。

add_edge 顺序 条件边分支 循环回连
二 · 状态图长什么样
三 · 线性等价于 LCEL，价值在非线性

线性场景 ≈ LCEL

纯顺序管道：A → B → C，没有分支和回首。

  • prompt | llm | parser 用 LCEL 更简洁
  • LangGraph 在此场景是「重一点的 LCEL」
  • 无需图的表达力，就用更轻的方案

真正价值 非线性能力

当流程需要「看情况走」和「反复走」时，图才显威力。

  • 分支：条件边按 State 选下一步（Day32 路由）
  • 循环：节点回连自己/上游（ReAct、重试、Plan-Execute）
  • 持久化状态：checkpointer 跨调用保存（Day35）
  • 三者叠加 = 可控、可观测、可中断恢复的 Agent
四 · 能力 → 课程映射

分支条件边路由

结构化输出决定走哪条（Day32），supervisor 多 Agent（Day39），意图分流（RAG/SQL/闲聊）。

循环节点回连

ReAct 想→做→看（Day30）、RetryPolicy 重试（Day31）、Plan-and-Execute 按 cursor 执行（Day33）。

持久化状态checkpointer

多轮记忆、中断恢复（Day35 / Day36 HITL）、多用户 thread_id 隔离、上下文摘要（Day35）。

可观测串起三者

stream_mode 看每步（Day34）、轨迹落盘定位分支/循环出错点——生产护城河。

画板对应洞察：State 贯穿 · Node 读写 · Edge 定序 → 线性 = LCEL；分支 / 循环 / 持久化才是 LangGraph 的护城河。
