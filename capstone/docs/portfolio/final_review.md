# 模拟面试与证据复盘（Day71）

> 目标不是“答得像标准答案”，而是确认每个项目结论都能指向代码、测试或报告，并找出三个下一步行动。

## 45 分钟流程

### 1. 自我介绍与项目讲解（5 分钟）

按 `capstone/docs/portfolio/project_pitch.md` 讲并录音。回放时检查：

- 是否先说解决的问题，再说组件；
- 数字是否包含样本量、日期和环境；
- 是否区分“已实现”“本地验证”“设计预留”和“尚未验证”；
- 是否误把 Dockerfile 当部署、把工作流当分支保护、把 6/6 当总体准确率。

### 2. 项目深挖（15 分钟）

每题至少回答“风险—实现—证据—剩余边界”四层：

1. 权限为什么不能靠 Prompt？指向 `capstone/knowledge_base.py` 的查询前 ACL 和相应测试。
2. 评测集怎么构造？当前 6 条能证明什么、不能证明什么？
3. CI 检查如何失败？为什么还要在 GitHub 配置 required status check？
4. 缓存怎样避免跨用户、跨角色和知识版本串用？
5. 成本优化省了多少？当前没有受控实验数字时，应明确回答“尚未测量”，再给实验设计。
6. 本地 fake 压测为什么不能回答生产容量？

### 3. RAG、Agent 与企业场景（20 分钟）

题目从 `capstone/docs/portfolio/rag_agent_interview.md` 和 `capstone/docs/portfolio/enterprise_interview.md` 抽取。优先覆盖：

- 检索错误与生成错误如何分层诊断；
- Chain 与 LangGraph 的选择标准；
- `InMemorySaver`、SQLite 和多实例持久化的边界；
- 文档 ACL、多租户目录、JWT、限流分别解决什么问题；
- Prompt/RAG/微调如何按失败原因选择；
- 内容审核异常时为什么要失败关闭；
- 客户端 p95 与服务端 p95 为什么不能简单当成逐请求排队时间。

### 4. 反问（5 分钟）

准备 2–3 个能帮助判断岗位成熟度的问题，例如：

- 团队如何构造和维护线上 bad case？
- 自动评审是否做过人工一致性校准？
- 身份、文档 ACL 和工具授权由哪个系统提供？
- 发布门禁、线上监控和事故复盘如何衔接？

不要预设所有团队都有完整 LLMOps；反问的目的是获取信息。

## 三个必须闭环的薄弱点

1. 问题：___；缺少的证据：___；动作：在 ___ 前运行/补充 ___。
2. 问题：___；缺少的证据：___；动作：在 ___ 前运行/补充 ___。
3. 问题：___；缺少的证据：___；动作：在 ___ 前运行/补充 ___。

“再看看”“再复习”不算动作。合格动作应能验收，例如“新增 10 条权限评测并让 CI 通过”“用 5/10/20 用户跑三轮稳态压测并记录环境”。
