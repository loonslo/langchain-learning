# 面试题准备：企业工程与上线（Day69）

> 企业级不是组件清单，而是身份边界、失败语义、数据隔离、恢复能力和可核验证据。

## 可靠性与成本

**Q：模型 API 超时或限流怎么办？**

`common.get_reliable_llm()` 设置单次超时并使用带抖动的指数退避。重试只适合无副作用或有幂等键的操作，并要遵守供应商的 `Retry-After` 和总时限。代码支持同一 provider 下的备用模型名，但当前没有第二套独立 provider 凭据，所以不能宣称已经实现跨供应商容灾。

**Q：怎么降本？**

当前实现有权限/租户/模型/知识版本感知的精确 TTL 缓存，以及“短问题可选轻量模型”的基础路由。它没有语义缓存，也没有已经验证的成本节省百分比。正确做法是先记录 token、价格、命中率和质量基线，再逐项实验；没有数据就只讲机制，不报节省数字。

**Q：成本怎么监控？**

`capstone/monitoring.py` 按请求记录 token、估算成本、模型和缓存命中，并支持租户范围的窗口指标和 UTC 日趋势。前提是 `.env` 配置真实输入/输出单价；默认价格为 0，因此默认报告不能当真实账单。

## 权限、租户与认证

**Q：为什么文档权限必须在检索前做？**

无权 chunk 一旦进入候选结果、缓存、日志或 Prompt，就已扩大泄露面。当前向量查询直接带 ACL filter，BM25 只在授权文档子集上建索引；`can_see()` 是本地同语义判定和测试辅助，不是召回后的补救过滤。缓存键还包含用户和角色，避免授权结果串用。

**Q：多租户怎么隔离？**

项目为每个租户使用独立 Chroma 目录，并校验租户 ID；查询时再检查身份租户是否匹配。物理目录降低漏写过滤条件的风险，但真正生产还需对象存储、备份、密钥、指标和运维权限的租户隔离，以及跨租户回归测试。

**Q：认证怎么做？**

当前本地实现验证 HS256 JWT 的签名、issuer、audience、有效期和必需 claims，再从 claims 构造身份；缺失或无效 token 返回 401。生产更常接企业 IdP/JWKS、密钥轮换和撤销机制。开发签发 token 的函数不是生产登录系统，且生产配置会禁止开发登录端点。

**Q：限流有什么边界？**

开发模式可用单进程内存限流；多 worker/多副本必须使用共享 Redis。限流按租户只是一个维度，生产通常还要按用户、接口、模型配额和并发数控制，并区分 429 与上游 503。

## CI、监控与性能

**Q：CI 评测门禁怎么工作？**

工作流运行生产边界测试、真实模型回归和 `capstone.ci_gate`，阈值不满足时检查失败，并上传报告。GitHub Actions 失败本身不一定阻止合并；仓库还必须把该检查配置为分支保护的 required status check。当前本地报告是 6 条用例全过，不夸大成大规模基准。

**Q：监控为什么看 p95/p99？**

分位数能暴露长尾，但必须同时报告样本量、窗口和流量分层。`capstone/monitoring_cli.py` 在样本不足时返回 `insufficient_data`，而不是误报健康；通知去重、静默和升级交给 Alertmanager 等外部系统。SQLite 指标适合单机演示，生产多副本应接统一指标后端。

**Q：Chroma 能不能上生产？**

不能按产品名一刀切。选型要看数据规模、并发、备份恢复、多租户、过滤能力、团队运维和服务等级。当前项目用租户独立 Chroma 完成本地闭环；`capstone/vector_store_pg.py` 提供 pgvector 的可选接法，要求外部迁移安装扩展、显式连接串、确定性文档 ID 和查询前 ACL。没有真实 Postgres 压测前，不宣称迁移后一定更快。

**Q：内容安全和合规怎么做？**

`capstone/content_safety.py` 实现本地确定性规则、外部审核器接口、输入输出双审、失败关闭和只存指纹的审计事件，`capstone/security.py` 负责响应 PII 脱敏。本地词表不是完整合规能力；适用法规、备案、数据留存和人工复核要求取决于地区、用户范围和业务场景，需由法务/合规按最新要求确认。

**Q：模型供应商能否无缝切换？**

统一工厂能减少业务层改动，但 provider 并不完全等价：工具调用、结构化输出、上下文长度、地区、认证、重试语义和价格都不同。`common.py` 会先校验配置并暴露保守的能力声明；切换后仍须跑契约测试和质量回归。

**Q：系统能扛多少并发？**

只能用特定环境的压测报告回答。2026-07-29 的本地假上游冒烟测试为 2 用户、5 秒、50ms 模拟上游，23 个请求、0 失败、6.033 rps、聊天 p95 80ms；这证明压测链路可运行，不是容量上限。要给生产容量结论，需逐级加压到拐点，并记录硬件、worker 数、缓存策略、上游限额和稳定持续时间。
