# 面试题准备：RAG 与 Agent（Day68）

> 回答结构：先给判断标准，再讲项目当前实现，最后说明还没做什么。

## RAG

**Q：RAG 为什么会答错？怎么区分检索错和生成错？**

先保存本次请求的召回文档、排序分数、最终上下文和答案。标准答案所需证据不在召回结果里，优先定位检索；证据已在上下文但答案不忠实，优先定位生成。项目的失败库目前用关键词做粗分类，这适合小型回归，不等同于完整忠实度评估；生产还需要抽样人工标注或经过校准的评审器。

**Q：chunk size 怎么选？**

没有通用最佳值。项目默认 300 字符、重叠 50，只是中文短文档的起点。选型要同时看召回率、上下文精度、答案质量、token 和延迟，并按标题、段落、表格或代码结构切分。只有在固定评测集上做对照后，才能声称某组参数更好。

**Q：怎么构造 RAG 测试集？**

从真实用户意图和高风险边界抽样，至少覆盖可回答事实、不可回答问题、相近概念、权限隔离、文档更新和引用来源。每条保存稳定 ID、问题、期望行为、判定规则和数据版本。当前 capstone 只有 6 条基础用例（4 条关键词、2 条拒答），所以结论只适用于这 6 条；跨文档、引用正确性和权限场景应继续扩集。

**Q：混合检索解决什么？**

向量检索擅长语义相似，BM25 对编号、缩写和精确词更敏感。项目对两路结果做秩融合，并在两路检索前都应用授权边界。是否优于单路检索必须通过同一评测集的消融实验验证，不能只凭架构名称判断。

**Q：答案带来源就等于可信了吗？**

不等于。模型可以生成一个看似真实但不存在的文件名。当前实现会移除模型自写的来源标记，再根据实际召回文档追加去重后的来源；这保证“引用来自召回”，但还不能证明某句话被该来源充分支持。句子级引用一致性仍需单独评测。

## Agent / LangGraph

**Q：什么时候用 Chain，什么时候用 LangGraph？**

固定、短、无恢复需求的流程优先用 LCEL/普通函数，复杂度更低。存在循环、条件路由、暂停恢复、长任务状态或人工审批时再用 LangGraph。不是“Agent 必须用图”，而是状态机语义是否值得引入。

**Q：状态怎么持久化？怎么防失控？**

当前项目的 HITL 演示使用 `InMemorySaver`，只支持进程内状态，重启即丢。生产需换持久化 checkpointer，并为 thread/tenant 建隔离、TTL、加密和迁移策略。循环还要有最大步数、超时、预算、工具白名单和取消机制，不能只依赖一个 `recursion_limit`。

**Q：高风险工具怎么做 HITL？**

在副作用执行前暂停，把动作摘要、参数、风险和幂等键交给经过授权的审批者；批准后用一次性、限时凭据恢复，并记录审计。项目目前只演示 `interrupt()` 后发布文本，没有真实删除、发送或支付权限，也没有交付上述生产控制。

**Q：MCP 在项目里解决了什么？**

MCP 是工具和资源的标准化接入协议。仓库 day40 有独立练习，但当前 capstone 没接 MCP，因此准确回答是“理解并练习过协议接法，尚未把它纳入毕业项目运行链路”，不能说项目已经通过 MCP 集成企业系统。

## 选型与运行

**Q：Prompt、RAG、微调怎么选？**

先按失败原因选工具：指令不清或输出格式不稳，先改 Prompt/约束；缺少最新或私有事实且要求溯源，优先 RAG；需要稳定改变模型行为、风格或领域模式且有足够数据和评测，再考虑微调。三者可以组合，选择还受隐私、延迟、成本和维护频率约束，不是固定的单向升级路线。

**Q：怎么降低幻觉？**

把问题拆成可测环节：检索覆盖率、排序质量、上下文权限、生成忠实度和无证据拒答。相应措施包括结构化切分、混合检索、查询改写、重排、上下文约束、确定性引用和拒答门槛；每项优化都要用回归集和失败分析验证。

**Q：Prompt 改了怎么回归？**

固定数据、模型参数和评测口径，跑版本化用例并保存失败样本；CI 在指标低于阈值时失败。线上监控的延迟、错误率、token 和成本不能直接代表幻觉率，答案质量需要抽样标注或经过验证的自动评审。
