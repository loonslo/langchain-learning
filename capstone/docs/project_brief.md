# 企业客服与工单 Copilot · Project Brief

## 问题

企业客服需要同时查阅产品文档、内部制度和本人有权访问的工单数据。人工切换系统慢，直接让模型自由访问全部数据又会带来越权、幻觉和不可审计的风险。

## 用户与角色

- 客服：查询授权知识、查询本人负责的业务记录、生成回复草稿。
- 主管：审批对外发布等高风险动作，并查看团队级运行指标。
- 租户管理员：管理本租户文档、权限、同步和知识版本。
- 平台运维：发布、监控、告警、备份、恢复和事故处理，不默认读取业务正文。

## 核心用户旅程

1. 用户通过可信 JWT 进入所属租户。
2. 系统对输入做边界校验、限流和安全审核。
3. 结构化路由选择知识检索、受控数据查询或高风险工作流。
4. 所有数据访问都在查询前应用租户和 ACL；身份参数不能来自 Prompt。
5. 高风险副作用先持久化，再由授权审批者使用一次性凭据恢复。
6. 输出经过引用绑定、内容审核和 PII 脱敏后返回。
7. 请求产生不含明文敏感内容的指标、日志、trace 和质量证据。

## 第一版范围

- TXT、Markdown、PDF 文档摄取和增量同步。
- 混合检索、真实召回引用、无证据拒答和上下文预算。
- JWT、多租户、文档 ACL、身份感知缓存和限流。
- 受控 query catalog；不执行 LLM 自由生成的 SQL。
- 可恢复的 Agent/HITL、显式同意的用户偏好记忆。
- 输入输出安全、自动评测、CI、监控、压测和部署准备。

## 非目标

- 不把本地 HS256 登录演示描述为企业 IdP。
- 不把词表描述为完整合规方案。
- 不把 fake 压测描述为生产容量。
- 不把 Dockerfile、迁移模板或公网可达描述为生产就绪。
- 不为了使用 Agent 而把确定性流程改造成 Agent。

## 质量与运行目标

- 跨租户、越权文档、缓存串号和可信身份伪造必须零容忍。
- PR 必须通过确定性离线测试；真实模型评测按 nightly/release 分层运行。
- `/live` 只表示进程存活；`/ready` 必须反映关键本地依赖状态。
- 所有质量数字必须同时记录数据集版本、样本量、模型、配置、时间和环境。
- 发布前必须有回滚步骤；涉及持久化状态的变更必须有恢复演练。

## 完成定义

一个能力只有同时满足以下条件才算进入项目：

1. 位于 `capstone/` 的实际运行路径中；
2. API、CLI 和评测共享同一业务契约；
3. 有正向、负向或故障测试；
4. 有可复现命令和证据产物；
5. 明确记录仍未验证的边界。
