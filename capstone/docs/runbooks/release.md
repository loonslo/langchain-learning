# Staging 发布与回滚 Runbook（Day71）

## 发布前

1. 记录 commit、镜像 digest、配置版本、知识 manifest 和评测集版本。
2. 运行 `pytest capstone/test_production.py -q`。
3. 运行 nightly/release 真实模型门禁并保存 artifact。
4. 验证迁移有向前和回退路径；备份已完成且恢复演练未过期。
5. 确认本次 feature flag、SLO、告警负责人和回滚决策人。

## Staging

1. 使用与生产相同的镜像和配置 schema 部署，不复用生产数据或密钥。
2. 验证 `/live`、`/ready`、未认证 401 和授权知识问答。
3. 验证一个无权文档、一个跨租户请求、一个安全审核失败和一个审批恢复。
4. 运行短时容量 smoke，比较客户端与服务端指标。

## 灰度

1. 先启用内部测试租户，再逐步扩大租户或流量比例。
2. 同时观察错误率、p95、拒答、人工升级、token 和成本。
3. 任何安全边界失败立即停止灰度，不等待样本量积累。

## 回滚

1. 停止继续放量并关闭新 feature flag。
2. 回滚到上一镜像 digest；数据库只能回滚到兼容 schema。
3. 若知识版本变化，恢复上一 manifest/索引并清除租户答案缓存。
4. 重新执行身份、ACL、引用和关键业务 smoke。
5. 记录回滚原因、影响范围和后续修复入口。

当前边界：仓库提供流程和本地检查，但没有可核验的 staging URL 或真实灰度记录。
