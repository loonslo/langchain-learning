# 备份与恢复 Runbook（Day72）

## 需要备份的状态

- 业务数据库和受控查询所依赖的 schema 版本。
- 知识源文件、ACL sidecar、同步 manifest 和向量索引。
- 长期偏好、审批/checkpoint 和必要的审计记录。
- 评测集、阈值、Prompt、模型/provider 与 embedding 配置版本。

密钥不进入普通数据备份；由 secret manager 独立管理和轮换。

## 一致性要求

- SQLite 演示环境必须停止写入或使用 SQLite backup API，不能只复制主文件并忽略 WAL。
- Postgres 使用平台快照或 `pg_dump`/PITR，恢复账号与应用账号分离。
- 向量索引可以从版本化知识源重建，但必须验证重建耗时是否满足 RTO。
- ACL 收紧和删除请求必须在恢复后仍然生效，不能因恢复旧索引重新泄露。

## 恢复演练

1. 恢复到一个全新的隔离目录或数据库实例，禁止覆盖当前环境。
2. 校验备份 manifest 和文件哈希。
3. 启动服务并检查 `/ready`。
4. 运行跨租户、缺 ACL、审批防重放和长期记忆删除测试。
5. 运行版本化质量评测并比较恢复前后的来源与指标。
6. 记录实际 RPO、RTO、失败步骤和修复动作。

当前边界：尚未生成真实云数据库 PITR 或对象存储恢复证据，因此不能声明满足生产 RPO/RTO。
